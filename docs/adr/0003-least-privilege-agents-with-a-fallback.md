# ADR 0003：AI 玩家最小权限，失败就回退

- 状态：已采纳（v0.6 起；v0.9 扩展到每个座位一个模型）
- 相关：[`architecture.md`](../architecture.md) 第 5、8 节，[`threat-model.md`](../threat-model.md)，[`evidence/agent-evaluation.md`](../evidence/agent-evaluation.md)

## 背景

模型会超时、会返回坏 JSON、会拒答、会被别的玩家的发言带偏，服务也会挂。一局游戏里一个 AI 座位要行动三十多次，任何一次卡住，整桌人都在等。

同时，一个 AI 座位只该知道真人坐在那个位置上能知道的东西。

## 决定

**每个 AI 座位只拿到自己的视图，只能提出自己合法的动作；模型一次不行就带原因重试一次，再不行由会推理的机器人代打。**

| 环节 | 做法 |
| --- | --- |
| 输入 | `build_observation` 只从该座位的 `PlayerView` 和公开记录构造；别人的昵称、发言、自己的笔记都只作为 JSON 字符串值出现，系统提示是固定文本 |
| 输出 | 结构化输出 + 严格类型检查；没有“谁在行动”字段，动作一律以本座位名义发出；玩家 id 必须来自该动作的 `targets` |
| 重试 | 最多 2 次调用；第二次带上被拒绝的原因 |
| 回退 | 超时、坏输出、拒答、服务不可用、预算用完 → 内置机器人（`table_bot`）按同一个视图行动，并在界面上标“由机器人代打”和原因 |
| 费用 | 按量计费的 API 每局有 token 上限；本机 Claude Code / Codex 用订阅额度，只计数不截断 |
| 时机 | 模型回合在后台线程跑，不阻塞真人的请求；前端轮询拿到结果 |
| 记录 | 每个回合的输入、每次回答、拒绝原因、耗时都存进 `agent_turns`，回放时能看到 |

## 后果

好处：

- 游戏永远能继续：替身模型故意捣乱（9 种方式轮流）跑 141 例，65% 的回合被回退，最终动作仍然 100% 合法，没有一个秘密被发出去。
- 真实模型的失败是可见、可统计的：Codex 149 例里 2 例超时代打，回放里能看到是哪一步、为什么。
- 被说服最多只能下一步“合法的烂棋”。Codex 在 8 个发言注入用例里都没照做。

代价：

- 回退的机器人比模型弱的时候，玩家会感觉 AI “忽强忽弱”；所以界面上必须标出来。
- 本机客户端很慢（Codex P95 约 48 秒），适合观战，不适合真人等它。
- 两次调用的上限意味着偶尔能修好的回答也被放弃了，换来的是可预测的延迟。

## 没有选的方案

| 方案 | 为什么不选 |
| --- | --- |
| 失败就无限重试 | 延迟和费用都没有上限 |
| 失败就随机合法动作 | 比机器人弱太多，一次超时就可能送掉一局 |
| 让模型看完整状态、靠提示词保密 | 秘密进了上下文就可能泄露，提示词挡不住 |
